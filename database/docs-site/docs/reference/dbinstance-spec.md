# DBInstance spec reference

`DBInstance` is a namespaced resource: group `dbaas.opencloud.wso2.com`, version `v1alpha1`, kind `DBInstance`, short name `dbi`. It has a `status` subresource. Everything it creates (VM, disks, Secrets, Service, ServiceMonitor) lives in the same namespace.

You can also read the field descriptions straight from the cluster: `kubectl explain dbinstance.spec.<field>`.

Smallest valid example:

```yaml
apiVersion: dbaas.opencloud.wso2.com/v1alpha1
kind: DBInstance
metadata:
  name: dbinstance-sample
spec:
  dbInstanceClass: db.t3.medium
  allocatedStorage: 50
  networkRef: default/vm-net-100
```

## At a glance

| | Fields |
| --- | --- |
| **Required** | `dbInstanceClass`, `allocatedStorage`, `networkRef` |
| **Can change later** | `dbInstanceClass`, `allocatedStorage` (grow only), `running`, `deletionProtection` |
| **Fixed at creation** | `networkRef`, `engineVersion`, `dbName`, `masterUsername`, `port`, `storageType`, `vmPassword`, and whether `backup` is set |
| **Not implemented** | `manageMasterUserPassword`, `masterUserPasswordRef`, `multiAZ`, `dbParameterGroupRef`, `tags` (accepted but ignored) |

**Name.** `metadata.name` can be at most 52 characters: lowercase letters, digits and `-`, starting and ending with a letter or digit. It's checked at creation.

:::note[What happens if you change a fixed field]
- `networkRef`, `engineVersion` and `vmPassword` are rejected immediately when you apply the change.
- `dbName`, `masterUsername`, `port` and `storageType` are accepted, then refused by the operator. The instance shows `ImmutableFieldChanged` and phase `incompatible-parameters`.
- In both cases, revert the change or recreate the instance. See [Status and conditions](/reference/status-and-conditions).
:::

## Sizing

| Field | Required | Default | Change later? | Notes |
| --- | --- | --- | --- | --- |
| `dbInstanceClass` | yes | | yes | Sets the VM's CPU, memory and PostgreSQL `max_connections`. An unknown class fails with `InvalidClass`. Changing it restarts the VM (cold resize). See [Resize and power](/operations/resize-and-power). |
| `allocatedStorage` | yes | | grow only | Data disk size in GiB, at least 1. Shrinking is rejected. Growing restarts the VM. |
| `storageType` | no | `longhorn` | no | The StorageClass for the data disk. The default comes from the operator's `databaseDefaults.storageClass`. |

**Instance classes.** The list below is the built-in default. Operators can change it, see [Operator configuration](/configuration/operator-config#instance-classes).

| Class | vCPU | Memory (MiB) | Max connections |
| --- | --- | --- | --- |
| `db.t3.micro` | 1 | 1024 | 50 |
| `db.t3.small` | 1 | 2048 | 100 |
| `db.t3.medium` | 2 | 4096 | 150 |
| `db.t3.large` | 2 | 8192 | 200 |
| `db.t3.xlarge` | 4 | 16384 | 300 |
| `db.m5.large` | 2 | 8192 | 200 |
| `db.m5.xlarge` | 4 | 16384 | 400 |
| `db.m5.2xlarge` | 8 | 32768 | 600 |
| `db.m5.4xlarge` | 16 | 65536 | 1000 |
| `db.r5.large` | 2 | 16384 | 300 |
| `db.r5.xlarge` | 4 | 32768 | 500 |
| `db.r5.2xlarge` | 8 | 65536 | 800 |

## Database

| Field | Required | Default | Change later? | Notes |
| --- | --- | --- | --- | --- |
| `engineVersion` | no | the image's default version | no | PostgreSQL major version, such as `"16"`. Put it in quotes so YAML doesn't read it as a number. It must be supported by the database image, or the instance fails with `OSImageInvalid`. |
| `dbName` | no | the instance name, made valid (`orders-db` becomes `orders_db`) | no | The first database created. Lowercase letters, digits and `_`, up to 63 characters, starting with a letter or `_`. Can't be `postgres`, `template0` or `template1`. |
| `masterUsername` | no | `dbadmin` | no | The administrator role. Same naming rules as `dbName`. Can't be `postgres` or `postgres_exporter`, and can't start with `pg_`. |
| `port` | no | `5432` | no | The PostgreSQL port, 1-65535. Shown in `status.endpoint.port`. |

The password is generated by the operator. See [Credentials](/security/credentials).

### `spec.vmPassword`

Sets a console and SSH password for the VM's `ubuntu` user. **For development only.** No password login exists by default. It can't be changed after creation.

## Networking

See [Networking](/networking) for how it fits together.

| Field | Required | Default | Change later? | Notes |
| --- | --- | --- | --- | --- |
| `networkRef` | yes | | no | The network the VM connects to, as `namespace/name` (a Harvester network attachment). It must already exist, and it needs outbound internet access for first boot. The operator doesn't check that it exists. |
| `dnsServerIP` | no | KubeVirt default | applied only at VM creation | Sets the VM's DNS server. Use it only when the cluster's DNS can't be reached from the VM. |

## Lifecycle

| Field | Default | Change later? | Notes |
| --- | --- | --- | --- |
| `running` | `true` | yes | `false` stops the VM and keeps its storage. A crash-loop-halted instance won't start even if this is `true`. See [Resize and power](/operations/resize-and-power). |
| `deletionProtection` | `false` | yes | While `true`, deleting the instance is blocked (`DeletionProtected`). Set it to `false` to allow deletion. See [Lifecycle and deletion](/operations/lifecycle-and-deletion). |

## Backup and restore

See [Backup and restore](/backup-restore/overview).

### `spec.backup`

Turns on backups. **It can only be set when the instance is created.** Without it, snapshots are rejected (`SourceBackupDisabled`) and no automated snapshot is ever taken. You can edit the settings inside it later. `backup: {}` is valid and gives you all the defaults.

| Field | Default | Notes |
| --- | --- | --- |
| `automated.enabled` | `true` | Turns daily snapshots and pruning on or off |
| `automated.retainCount` | `7` | How many of the newest successful automated snapshots to keep. At least 1. |
| `automated.preferredWindowUTC` | `02:00-03:00` | `HH:MM-HH:MM` in 24-hour UTC. An end before the start crosses midnight. |

```yaml
spec:
  backup:
    automated:
      enabled: true
      retainCount: 7
      preferredWindowUTC: "02:00-03:00"
```

Details: [Automated backups](/backup-restore/automated-backups).

:::note[No point-in-time recovery]
Continuous WAL archiving is not configured in this release. A restore recovers only what the snapshot captured. See [What is not implemented](/backup-restore/overview#what-is-not-implemented).
:::

### `spec.restoredFrom`

Set automatically by the restore process on a database created by a [restore](/backup-restore/restore). **Don't set it yourself.** It can't be changed after creation, and it records where the database came from, even after the restore, the snapshot and the source are deleted.

## Not implemented

These fields are accepted but ignored:

| Field | Notes |
| --- | --- |
| `multiAZ` | No standby VM is created |
| `dbParameterGroupRef` | The `DBParameterGroup` resource doesn't exist |
| `tags` | Not passed on to child resources or dashboards |
| `manageMasterUserPassword`, `masterUserPasswordRef` | Reserved; the operator always generates the password |

## Defaults summary

| Field | Value | Set by |
| --- | --- | --- |
| `running` | `true` | CRD |
| `dbName` | the instance name, made valid | operator |
| `masterUsername` | `dbadmin` | operator (`databaseDefaults.masterUsername`) |
| `port` | `5432` | operator (`databaseDefaults.port`) |
| `storageType` | `longhorn` | operator (`databaseDefaults.storageClass`) |
| `engineVersion` | the image's default | operator |
| `backup.automated.enabled` | `true` | CRD |
| `backup.automated.retainCount` | `7` | CRD |
| `backup.automated.preferredWindowUTC` | `02:00-03:00` | CRD |

The operator never writes defaults back into `spec`. The values it actually used are recorded in `status.appliedSpec` once the VM is created.

## Full example

```yaml
apiVersion: dbaas.opencloud.wso2.com/v1alpha1
kind: DBInstance
metadata:
  name: orders
  namespace: tenant-a
spec:
  dbInstanceClass: db.m5.large
  allocatedStorage: 100
  engineVersion: "16"
  dbName: orders
  masterUsername: orders_admin
  port: 5432
  storageType: longhorn
  networkRef: default/vm-net-100
  backup:
    automated:
      retainCount: 7
      preferredWindowUTC: "02:00-03:00"
  running: true
  deletionProtection: true
```
