# Samples

The repository ships manifests under `database/config/samples/`. All of them target `networkRef: default/vm-net-100`; replace it with the NAD of your own VLAN, and create the instance in the namespace of your choice.

| File | Purpose | In `kustomization.yaml` |
| --- | --- | --- |
| `dbaas_v1alpha1_dbinstance.yaml` | Minimal instance with a generated password. | yes |
| `dbaas_v1alpha1_dbinstance_byo_password.yaml` | Instance whose master password you supply through a Secret. | no, on purpose |
| `kustomization.yaml` | Lists only the first sample. | n/a |

## `dbaas_v1alpha1_dbinstance.yaml`

```yaml
apiVersion: dbaas.opencloud.wso2.com/v1alpha1
kind: DBInstance
metadata:
  labels:
    app.kubernetes.io/name: dbaas
    app.kubernetes.io/managed-by: kustomize
  name: dbinstance-sample
spec:
  dbInstanceClass: db.t3.medium
  allocatedStorage: 50
  engineVersion: "16"
  dbName: myapp
  masterUsername: dbadmin
  manageMasterUserPassword: true
  # networkRef points at an existing Harvester Multus NAD (namespace/name).
  networkRef: default/vm-net-100
  backupRetentionPeriod: 7
  deletionProtection: true
  running: true
```

What it does:

- Creates a 2 vCPU, 4096 MiB VM with `max_connections` 150 (`db.t3.medium`) and a 50 GiB data volume on the default StorageClass.
- Runs PostgreSQL 16 with an initial database `myapp` and administrator role `dbadmin`.
- The password is generated by the controller. `manageMasterUserPassword: true` is a reserved field the controller does not read, so it has no effect; omit it in your own manifests. Retrieve the generated password from the Secret `pg-dbinstance-sample-credentials`.
- `backupRetentionPeriod: 7` is accepted but inert: no backup runs in v0.1.0, and without `s3BackupConfig` the VM's bootstrap file records backups as disabled.
- `deletionProtection: true` means `kubectl delete` will not tear the instance down until you set it to `false`.

Apply it and watch it:

```bash
kubectl apply -f database/config/samples/dbaas_v1alpha1_dbinstance.yaml
kubectl get dbi -w
kubectl wait --for=condition=Ready dbinstance/dbinstance-sample --timeout=15m
```

To remove it:

```bash
kubectl patch dbinstance dbinstance-sample --type merge -p '{"spec":{"deletionProtection":false}}'
kubectl delete dbinstance dbinstance-sample
```

## `dbaas_v1alpha1_dbinstance_byo_password.yaml`

A `DBInstance` whose master password is one you choose. The header comments of the file are part of the sample and are reproduced here.

```yaml
# A DBInstance whose master password is one YOU choose, instead of a generated one.
#
# 1. Create the password Secret in the SAME namespace as the DBInstance. It must have
#    this type, and the password must be 8-128 bytes of UTF-8 with no line break:
#
#      kubectl create secret generic orders-db-password \
#        --type=dbaas.opencloud.wso2.com/master-password \
#        --from-file=password=./password.txt          # printf, not echo: no trailing newline
#
#    (--from-literal works too, but puts the password in your shell history.)
#
# 2. Apply this manifest. The operator reads the Secret ONCE, keeps its own copy for
#    retries and repave, and never changes or deletes your Secret.
#
# Notes:
#  - `credentials` cannot be added, changed or removed after the instance is created.
#  - Editing your Secret later does NOT change the database password. The instance
#    reports status.credentials.sourceChanged=true and emits a Warning event.
#  - Do not name your Secret pg-<instance>-credentials, -connect or -cloudinit:
#    DBaaS creates and deletes Secrets with those names.
#  - Do not combine `credentials` with manageMasterUserPassword or masterUserPasswordRef.
#
# Not part of config/samples/kustomization.yaml on purpose: applying every sample with
# `kubectl apply -k config/samples` must not create an instance that waits for a Secret.
apiVersion: dbaas.opencloud.wso2.com/v1alpha1
kind: DBInstance
metadata:
  labels:
    app.kubernetes.io/name: dbaas
    app.kubernetes.io/managed-by: kustomize
  name: dbinstance-byo-sample
spec:
  dbInstanceClass: db.t3.medium
  allocatedStorage: 50
  engineVersion: "16"
  dbName: myapp
  masterUsername: dbadmin
  credentials:
    passwordSource:
      secretRef:
        name: orders-db-password
        key: password
  # networkRef points at an existing Harvester Multus NAD (namespace/name).
  networkRef: default/vm-net-100
  deletionProtection: true
  running: true
```

Behaviour to expect:

- If the Secret does not exist yet, `CredentialsReady` is `False` with reason `PasswordSourceNotFound` and the controller polls every 30 seconds, so creating the Secret afterwards unblocks the instance.
- A wrong Secret type, a missing key, a value outside 8 to 128 bytes, a line break in the value, or a reserved Secret name gives reason `PasswordSourceInvalid`.
- On success `status.credentials.source` is `UserProvidedSecret`, and the accepted password is copied into `pg-dbinstance-byo-sample-credentials` together with the `password-source-*` annotations.
- After creation, the `credentials` block is immutable.

See [Credentials](/security/credentials) and the [spec reference](/reference/dbinstance-spec#speccredentials).

## `kustomization.yaml`

```yaml
## Append samples of your project ##
resources:
- dbaas_v1alpha1_dbinstance.yaml
# +kubebuilder:scaffold:manifestskustomizesamples
```

`kubectl apply -k database/config/samples` therefore creates only `dbinstance-sample`.

## Minimal manifest

Only three fields are required:

```yaml
apiVersion: dbaas.opencloud.wso2.com/v1alpha1
kind: DBInstance
metadata:
  name: minimal
spec:
  dbInstanceClass: db.t3.micro
  allocatedStorage: 10
  networkRef: default/vm-net-100
```
